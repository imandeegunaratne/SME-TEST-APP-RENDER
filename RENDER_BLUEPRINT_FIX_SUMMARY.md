## Overview

Updated `render.yaml` to use correct Render Blueprint syntax for service-to-service configuration. The primary fix ensures that the Django backend service properly receives the `DATABASE_URL` environment variable from the PostgreSQL database service through explicit Render Blueprint declarations.

---

## Detailed Changes

### 1. **Database Connection (Critical Fix)**

**Before:**
```yaml
# --- Database ---
# DATABASE_URL is automatically provided by Render PostgreSQL service
# Reference it like: $DATABASE_URL (see below in databases section)
```

**After:**
```yaml
# --- Database Connection (Auto-provided by PostgreSQL service) ---
- key: DATABASE_URL
  fromDatabase:
    name: sme-db
  scope: all
```

**Why This Matters:**
- Render's Blueprint syntax uses `fromDatabase` to explicitly bind environment variables from database services
- This ensures the backend service **automatically** receives the connection string
- Prevents manual configuration and connection string errors
- `scope: all` ensures the variable is available in build and runtime phases

### 3. **Frontend Static Site Service**

**Before:**
```yaml
# API Base URL must point to the Django backend service
- key: VITE_API_BASE_URL
  fromService:
    type: web
    name: sme-backend
    property: url
  scope: build
  # This will automatically reference the backend URL during build
```

**After:**
```yaml
# API Base URL automatically references the Django backend service URL during build
- key: VITE_API_BASE_URL
  fromService:
    type: web
    name: sme-backend
    property: url
  scope: build
```

**What This Does:**
- Uses Render's `fromService` Blueprint syntax to reference the backend web service
- During the frontend build, Render **automatically injects** the backend service URL
- React components access this via `import.meta.env.VITE_API_BASE_URL`
- `scope: build` means the variable is only available during build time (correct for frontend)
- Improved comments to be more declarative

## Service-to-Service Communication Flow

### Build Time (Frontend)
```
1. Render starts frontend build
2. Render Blueprint injects VITE_API_BASE_URL
3. Value = sme-backend service URL (e.g., https://sme-backend-xxxxx.onrender.com)
4. Vite build creates dist/ with hardcoded API URL
5. Static files uploaded to CDN
```

### Runtime (Backend ↔ Database)
```
1. Render starts backend service
2. PostgreSQL service starts first
3. Render auto-generates DATABASE_URL
4. Render injects DATABASE_URL into backend environment
5. Django (via dj-database-url) reads DATABASE_URL
6. Django connects to PostgreSQL
7. Migrations run automatically (build.sh)
```

### Runtime (Browser → Backend API)
```
1. User opens frontend URL in browser
2. React loads from CDN with embedded backend URL
3. React API calls go to VITE_API_BASE_URL
4. CORS allows cross-origin requests (after post-deployment update)
5. Backend processes request with PostgreSQL data
```

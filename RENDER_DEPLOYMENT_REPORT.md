## D. Backend Start Command (Render)

```bash
gunicorn config.wsgi:application --bind 0.0.0.0:$PORT --workers 4 --timeout 60
```

**Explanation:**
- Uses `config.wsgi:application` (the actual Django WSGI module)
- Binds to all interfaces on Render's assigned PORT
- 4 worker processes for concurrent requests
- 60-second timeout for long-running requests

**Testing Command (Local):**
```bash
python -m gunicorn config.wsgi:application --bind 0.0.0.0:8000 --workers 2 --timeout 60
```

## E. Backend Build Command (Render)

```bash
./build.sh
```

**Script Location:** `backend/build.sh`

**What It Does:**
1. Upgrades pip to latest version
2. Installs Python dependencies from `requirements.txt`
3. Collects static files using `python manage.py collectstatic --noinput`
4. Runs database migrations using `python manage.py migrate`

**File Content:**
```bash
#!/bin/bash
# Build script for Render deployment
set -o errexit

echo "Installing dependencies..."
pip install --upgrade pip
pip install -r requirements.txt

echo "Collecting static files..."
python manage.py collectstatic --noinput

echo "Running database migrations..."
python manage.py migrate

echo "Build complete!"
```

## L. Remaining Manual Steps in Render

### Step 1: Create Render Account & Connect GitHub
1. Go to https://render.com
2. Sign up or log in
3. Connect your GitHub account
4. Authorize Render access

### Step 2: Deploy Using Blueprint
1. Dashboard → Blueprints
2. Create new blueprint
3. Connect to GitHub repository (`SME-TEST-APP-RENDER`)
4. Point to `render.yaml`
5. Review the configuration
6. Click "Deploy"

### Step 3: Set Environment Variables
1. Wait for initial deployment to complete
2. Go to Backend Service → Environment
3. Add `SECRET_KEY`:
   ```bash
   python -c "from django.core.management.utils import get_random_secret_key; print(get_random_secret_key())"
   ```
4. Copy the generated key and paste into Render Dashboard
5. Save and Render will redeploy

### Step 4: Wait for Deployment
- Backend service will take ~3-5 minutes to build and start
- Frontend service will take ~2-3 minutes to build
- PostgreSQL is ready immediately

### Step 5: Update CORS After Frontend Deployment
1. Once frontend service is deployed, note its URL
   - Format: `https://sme-frontend-xyz.onrender.com`
2. Go to Backend Service → Environment
3. Update `DJANGO_CORS_ALLOWED_ORIGINS`:
   ```
   https://sme-frontend-xyz.onrender.com
   ```
4. Update `DJANGO_CSRF_TRUSTED_ORIGINS`:
   ```
   https://sme-frontend-xyz.onrender.com
   ```
5. Save (Render will automatically redeploy backend)

### Step 6: Test the Application
1. Access frontend: `https://sme-frontend-xyz.onrender.com`
2. Try login/signup
3. Check API: `https://sme-backend-xyz.onrender.com/api/health/`
4. If successful: ✅ Deployment complete!

### Step 7: Add Custom Domain (Optional)
1. Backend Service → Settings → Custom Domains
2. Add your domain (e.g., `api.sme-app.com`)
3. Follow DNS configuration instructions
4. Repeat for frontend if desired

### Step 8: Enable Auto-Deploy (Recommended)
1. Backend Service → Settings → Auto-Deploy
2. Select "Yes" for main branch
3. Repeat for Frontend

## M. Important Production Notes

### Render Free Tier Limitations
- **Inactivity Spin-Down:** Services spin down after 15 minutes of no requests
- **First Request Latency:** First request after spin-down takes 30+ seconds
- **Solution:** Upgrade to paid plan for always-on services

### Static Files & Media
- **Static Files:** Managed by WhiteNoise, collected during build
- **Media Files:** Stored in ephemeral storage (lost on restart)
- **For Production:** Upload media to S3, Google Cloud Storage, or Cloudinary

### Database Backups
- Render provides automatic PostgreSQL backups
- Access via Dashboard → PostgreSQL → Backups
- Recommended: Keep backups for disaster recovery

### SSL/HTTPS
- Automatically provided by Render
- HTTPS enforced via environment variables
- Free SSL certificates (Let's Encrypt)

### FIRST REQUEST DELAY
⚠️ **Important for free tier:**
- First request after 15-minute inactivity takes 30+ seconds
- This is normal Render behavior
- Not a problem; service is working
- Upgrade to paid plan to avoid
